# Отпечаток SHA-256 сертификата боевого ключа подписи Android — контрольная
# точка смены ключа (.ultraplan/research/04-android-release.md §5, §7;
# apps/mobile/scripts/android-release-gate.mjs → expectedSignerGate).
#
# Строка ниже — точка отсчёта: производственная сборка (тег shagi-v*, пуш в
# ветку по умолчанию, ручной запуск с явным выбором production) сверяет с ней
# отпечаток, реально извлечённый из keystore в секретах репозитория.
# Расхождение — ВСЕГДА отказ сборки, а не предупреждение.
#
# Почему так строго. Подпись — это личность приложения: Android ставит
# обновление поверх установленного, только если она совпала. Молча принять
# здесь другой ключ значило бы молча испортить обновление всем, кто уже
# поставил ШАГИ, и узнали бы мы об этом от людей, а не от сборки. Поэтому
# расхождение видно сразу, на этом шаге, до получаса компиляции.
#
# Разработческие сборки (pull request, чужая ветка, ручной запуск без выбора
# канала) этот файл не читают вовсе — они собирают debug-APK постоянным
# отладочным ключом из apps/mobile/keys/, объяснение в keys/README.md.
#
# Менять строку ниже можно только вместе со сменой самого ключа, а сменить
# ключ можно только до первой публикации в сторе. После публикации новый
# ключ означает, что установленное приложение перестаёт обновляться.
#
# Секреты репозитория, из которых берётся сам ключ: ANDROID_KEYSTORE_BASE64,
# ANDROID_KEYSTORE_PASSWORD, ANDROID_KEY_ALIAS, ANDROID_KEY_PASSWORD.
