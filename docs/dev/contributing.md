# Соглашения

Правила, которые в этом репозитории не обсуждаются в каждом PR заново —
следствие замороженного ТЗ (`docs/spec/`) или решений в
`.ultraplan/open-questions.md`. Часть из них — блокирующий дефект на
приёмке, не вкусовщина.

## Язык

**Комментарии, сообщения об ошибках, названия тестов и коммиты — по-русски.**
Идентификаторы (имена файлов, переменных, типов) — по-английски: это код,
а не текст для пользователя.

Комментарий отвечает на вопрос «почему так», а не «что здесь написано»:
код и так говорит, что он делает; комментарий нужен там, где решение не
очевидно без контекста ТЗ или истории поломки. Хороший образец — заголовки
`src/index.ts` в каждом пакете: они объясняют границу ответственности
пакета, а не пересказывают его (пока пустое) содержимое.

```ts
// Плохо:
// увеличиваем счётчик на единицу
counter += 1;

// Хорошо:
// occurrence_seq стартует с 1 (open-questions ?3) — ноль зарезервирован,
// иначе он попадёт в UUIDv5 и «нулевой» occurrence станет неотличим от
// отсутствующего.
```

## Приоритет источников

При расхождении, если оно вообще возникнет:

```
docs/spec/SPEC/00_MASTER_IMPLEMENTATION_TZ.md   (замороженный контракт)
  > docs/spec/SPEC/*  (остальные инженерные документы)
    > docs/spec/DESIGN/*  (визуальный источник, приоритет — SPEC §15)
      > .ultraplan/open-questions.md  (принятые решения по недосказанному)
        > docs/adr/*  (архитектурные решения этого репозитория)
```

**`docs/spec/` и `assets/brand/` — чужие, замороженные документы.** Их
читают и на них ссылаются, но не редактируют ни при каких обстоятельствах —
это указано в `README.md` репозитория и проверяется
`docs/spec/SHA256SUMS.txt`.

## ADR

**Любое отклонение от стека или архитектуры SPEC фиксируется отдельным
ADR в `docs/adr/`, в том же PR, что и реализация.** Формат — файл
`docs/adr/NNNN-korotkoe-nazvanie.md` по шаблону
[`TEMPLATE.md`](../adr/TEMPLATE.md) (формат Nygard: Контекст / Решение /
Последствия, плюс шапка со статусом, датой и указанием, от чего именно
отклоняемся).

**Имя файла — латиницей, транслитерацией; заголовок внутри — по-русски.**
Так же у Записок (`0001-yadro-na-typescript-vmesto-rust.md`), и не из
вкуса: macOS хранит имена файлов в нормализации NFD, git — в NFC, и
кириллическое имя начинает двоиться между macOS-раннером (будущие
iOS/macOS сборки, SPEC §1.2) и Linux/Windows. Содержимое ADR пишется
по-русски, как и все документы проекта.

Номера **0001–0004 заняты** (тулчейн, пакет `i18n` — см. сами ADR);
**0002, 0003, 0005 зарезервированы** под пакеты работ, следующие за
E00.1 — не занимайте их до того, как соответствующий пакет работ дойдёт
до реализации.

## Границы пакетов

**Публичный API пакета — только `./src/index.ts`** (см. `exports` в
`package.json` каждого пакета — там ровно один путь). Глубокие импорты
вида `@shagi/core/src/internal/...` не работают на уровне резолвинга
модулей и не должны обходиться относительными путями между пакетами.

Направление зависимостей, зафиксированное SPEC §3 и заголовками пакетов:

```
apps/*  →  @shagi/app  →  @shagi/{core, storage, sync, nlp, importer, ui, platform, telemetry, i18n}
                                                              @shagi/{contracts}  (используется отовсюду, как форма данных)
```

`@shagi/ui` не импортирует `@shagi/i18n` и не содержит продуктовых строк
(см. заголовок `packages/ui/src/index.ts` и
[`0004-paket-i18n.md`](../adr/0004-paket-i18n.md)).

### Правило `apps/*`

`apps/*` появляются в следующем пакете работ (E00.5). Уже сейчас
действует инвариант SPEC §3: **ни одного экрана, ни одной строки
бизнес-логики в `apps/*`.** Оболочке не хватает способа что-то сделать —
значит не хватает порта в `@shagi/platform` (SPEC §4), а не повода для
ветвления по платформе внутри `@shagi/app`.

## Стиль кода

TypeScript в строгом режиме, конфиг общий — `tsconfig.base.json`:
`strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`,
`noImplicitOverride`, `noFallthroughCasesInSwitch`, `verbatimModuleSyntax`,
`isolatedModules`, `moduleResolution: bundler`, цель `ES2023`.

- `noUncheckedIndexedAccess` включён — доступ по индексу (массив, `Record`)
  даёт `T | undefined`; это обязательная проверка на границе, не
  небрежность, которую нужно обходить `as`.
- `exactOptionalPropertyTypes` включён — `{ a?: string }` не принимает
  явный `undefined`; для доменных temporal-полей (SPEC §5, §7.1) это
  различие «поле отсутствует» / «поле пустое» имеет смысл, а не шум.
- Импорты внутри пакета — с расширением `.js`, даже когда файл `.ts`
  (ESM + `moduleResolution: bundler`; Vite/Vitest резолвят такой импорт
  на реальный `.ts`-файл).
- Экспортируемые сущности снабжаются JSDoc со ссылкой на пункт SPEC,
  когда решение неочевидно без него.
- Никаких `any` в публичных сигнатурах.
- Пользовательские тексты — только из каталога `@shagi/i18n` (SPEC §13.1);
  захардкоженная строка в `@shagi/ui`/`@shagi/app` — блокирующий дефект.

## Линт и формат

`oxlint` — быстрый линтер, `prettier` — форматирование. Оба настроены на
уровне корня (`.oxlintrc.json`, `.prettierrc.json`); `packages/ui` и
`packages/app` дополнительно подключают правила адгезии дизайн-системы —
см. комментарий в их собственных `.oxlintrc.json` (запрет сырых hex-цветов,
сырых px и любых `font-family`, кроме `Geist`/`Geist Mono`, severity
`error` — решение по вопросу ?15 в `.ultraplan/open-questions.md`).

## Метод разработки

TDD RED → GREEN → REFACTOR: сначала тест, который падает по ожидаемой
причине, затем минимальный код, чтобы он прошёл. Перед тем как заявлять,
что что-то готово, — реально выполненная команда проверки, а не «должно
пройти». Подробности — в скиллах `test-driven-development` и
`verification-before-completion`.
