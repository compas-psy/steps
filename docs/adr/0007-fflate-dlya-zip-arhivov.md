# ADR-0007. `fflate` для ZIP-архивов импорта и бэкапа

Дата: 2026-09-02  
Статус: принято

## Контекст

`01§26` требует читать backup ZIP Todoist, `01§27` — отдавать собственный
бэкап `shagi-backup-v1.zip`. ZIP в обоих случаях не выбор реализации, а
часть контракта: имя файла и состав архива выписаны в ТЗ дословно.

Стек ТЗ (SPEC §2) библиотеки для архивов не называет — её там просто нет,
как нет и запрета. Поэтому решение фиксируется ADR: это добавление
зависимости, не описанной стеком.

Рассматривались три пути.

1. **Своя реализация поверх `CompressionStream`/`DecompressionStream`.**
   Оба API есть и в браузере, и в Node 24, и в WebView Tauri, так что
   `deflate` можно не писать. Но ZIP — это не только сжатие: локальные
   заголовки, центральный каталог, CRC32, EOCD, кодировка имён. Ошибка в
   любом из них — это либо не читающийся чужой архив, либо, что хуже,
   собственный бэкап, который не откроется тогда, когда он единственный
   остался.
2. **`jszip`.** Умеет больше, чем нужно, тянет зависимости и заметно
   больше по размеру — а импорт и экспорт живут в том же бандле, что и
   мобильная оболочка.
3. **`fflate`.**

## Решение

`fflate`, версия зафиксирована точкой — `0.8.2` (ADR-0001: версии
фиксируются точками, а не диапазонами).

Причины:

- MIT — проходит `check-license-allowlist.mjs` без исключения владельца;
- ноль собственных зависимостей — нечему протащить чужую лицензию следом;
- один и тот же код работает в браузере, в Node (тесты) и в WebView
  Tauri: отдельной ветки под платформу не нужно;
- синхронный API (`zipSync`/`unzipSync`) достаточен: границы `01§26`
  (сжатый ≤100 МБ, распакованный ≤500 МБ) заведомо укладываются в память,
  а поток усложнил бы код без выгоды.

Зависимость подключена **только** к `@shagi/importer`. Ни домен, ни
хранилище, ни UI о ней не знают: работа с архивом целиком заперта в
`src/backup/archive.ts`, и замена библиотеки затрагивает один файл.

## Последствия

- Появилась первая внешняя runtime-зависимость у `@shagi/importer`.
- Ограничения безопасности `01§26` (path traversal, вложенные архивы,
  число записей, размер) проверяются НАШИМ кодом в `archive.ts`, а не
  библиотекой: `fflate` распаковывает то, что дали, и не обязан судить о
  безопасности. Каждое ограничение имеет собственный тест.
- Если однажды понадобится потоковая распаковка (архивы больше памяти),
  у `fflate` есть асинхронный API — менять библиотеку не придётся.
