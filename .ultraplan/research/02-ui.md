**Важная находка по происхождению DS-бандла.** `docs/spec/DESIGN/design-system/` — это НЕ дизайн-система «ШАГИ», а слепок дизайн-системы соседнего продукта **СИМПАС / ПРАКТИКА** (`readme.md` строки 1–20: «СИМПАС… helping specialists… `cmpas.ru`»), поставленный в комплекте как источник токенов/компонентов/паттернов, которые ШАГИ **переиспользует как есть** (light-токены в `04_UI_DESIGN_SYSTEM.md` §3 побайтово совпадают с `tokens/colors.css`). Отличие ШАГИ от ПРАКТИКИ — только `--svc-shagi-bg:#3B8F5A` (светлый форест) вместо `--svc-praktika-bg:#1D4735` (тёмный форест) — см. `tokens/services.css` и `readme.md` §«Знаки сервисов». Компоненты в HTML-прототипе импортируются как `DesignSystem_66188c.<Name>` — это компоненты СИМПАС-бандла, а не готовые компоненты ШАГИ; `packages/ui` их не наследует по имени/пропсам буквально, а строит по духу токенов и паттернов.

### 1.2 Цвета — dark (`04_UI_DESIGN_SYSTEM.md` §4, идентично `[data-theme="dark"]` блоку в R1 HTML строки 24–41)

`--background:#10221A`, `--foreground:#EAF3EC`, `--card:#173326`, `--card-foreground:#EAF3EC`, `--popover:#173326`, `--muted:#1C3B2C`, `--muted-foreground:#9FB3A6`, `--secondary:#1C3B2C`, `--border:#24452F`, `--input:#1C3B2C`, `--ring:#D8AE67`, `--accent:#D8AE67` (fg `#142018`), `--primary:#3B8F5A` (fg `#0E1E16`), `--destructive:#E8695A` (fg `#1A0D0A`), плюс статусные soft/500-пары (blue/violet/orange/red/success/amber) и `--sage-50…300` пересчитанные под тёмный фон. Полный список см. §4 файла — 30+ переменных, ни одна не совпадает с light-набором один-в-один (это НЕ инверсия через `filter`, а отдельно посчитанная палитра).

**Переключение темы.** Механизм в прототипе — атрибут `data-theme` на корневом контейнере + CSS-селекторы `[data-theme="dark"]` переопределяют custom properties (см. R1 HTML строки 20–77). Продукт обязан поддерживать **System / Light / Dark** (§4, `12_SCREEN_STATE_MATRIX.md` M42); light — это `:root` без атрибута, dark — `[data-theme="dark"]`, System — следует `prefers-color-scheme` без явного атрибута. **`paper` / `graphite` / `ink`** — три дополнительных `[data-theme]` блока в прототипе (строки 43–77) — это showcase-компаратор тем семейства ЗАПИСКИ и **не входят** в продукт ШАГИ (`04_UI_DESIGN_SYSTEM.md` §1, §4; `12_SCREEN_STATE_MATRIX.md` «v2 theme showcase rule»; `14_DESIGN_V2_DELTA.md` §1). `packages/ui` должен физически не содержать эти три темы (ни токенов, ни SegmentedControl-опций).

### 1.4 Radius / Spacing (`04_UI_DESIGN_SYSTEM.md` §6, `tokens/radius.css`)

Radii: `8, 12, 16, 20, 24, 999` (pill). Spacing scale: `4,8,12,16,20,24,32,40,48`. `--container-max:1240px`, `--sidebar-width:240px` — из DS-бандла (desktop layout baseline). Touch target ≥44×44 логических px (§6).

### 1.5 Тени (`04_UI_DESIGN_SYSTEM.md` §6, `tokens/shadows.css`)

`--shadow-xs: 0 1px 2px rgba(20,32,24,.04)`, `--shadow-sm: 0 2px 8px rgba(20,32,24,.04)`, `--shadow-card: 0 8px 30px rgba(20,32,24,.06)`, `--shadow-card-hover: 0 10px 34px rgba(20,32,24,.09)`, `--shadow-floating: 0 14px 34px rgba(20,32,24,.10)` (+`--shadow-header` только в CSS-бандле). Правило: «No harsh shadow/glassmorphism-driven UI».

### 1.6 Шрифты (`04_UI_DESIGN_SYSTEM.md` §2)

- **Geist** 400/500/600/700 — UI.
- **Geist Mono** 400/500/600 — время/табличные/технические микротексты.
- Fallback-стек: `-apple-system, BlinkMacSystemFont, Segoe UI, Roboto, Helvetica Neue, Arial`.
- **Self-host обязателен**: «Fonts self-hosted/packaged. Runtime Google Fonts network dependency prohibited.» Это прямо противоречит поставленному `tokens/fonts.css` (строка 5: `@import url("https://fonts.googleapis.com/css2?family=Geist…")`) и caveat в `readme.md` (§Caveats: «Geist is loaded from Google Fonts — swap for self-hosted `.woff2` for offline use»). **Т.е. поставленный DS-бандл сознательно не production-ready по шрифтам — `packages/ui` обязан заменить `@import` на локальные `.woff2` файлы (лицензия Geist это разрешает, SIL Open Font License).** Нужно раздобыть/сгенерировать `.woff2` для 4 начертаний Geist + 3 начертаний Geist Mono (7 файлов минимум, ещё ×2 если понадобится italic — в спеке italic не упомянут).

### 1.7 Сервис-токены (`tokens/services.css`) — не токены ШАГИ, но релевантный контекст

9 пар «фон+дерево» для всех продуктов СИМПАС; для ШАГИ актуальна одна: `--svc-shagi-bg:#3B8F5A` / `--svc-shagi-fg:#F7F8F4`. `--icon-squircle:0.28` и `--icon-rounded:0.18` — доля скругления иконки приложения от стороны (используется для генерации иконок лаунчера, см. §8 ниже).

### 1.8 «base.css» — глобальные элементы

`color-scheme:light` на `:root` (в самом бандле light-only — продукту нужно расширить под dark/system), фон/цвет body из токенов, focus-ring через `box-shadow: 0 0 0 3px color-mix(in srgb, var(--ring) 45%, transparent)` на `:focus-visible` (не `outline`), `::selection` — `sage-200`/`forest-900`.

## 2. Компоненты

`04_UI_DESIGN_SYSTEM.md` §10 задаёт официальную иерархию, которую обязан покрыть `packages/ui` (домен: `packages/ui` = «tokens/components» — см. `00_MASTER_IMPLEMENTATION_TZ.md` §3, монорепо-дерево; сами экраны/маршруты живут в `packages/app`, не в `ui`).

### Foundations
Colors, type, spacing, radius, elevation, motion, icons, breakpoints — не React-компоненты, а токен-слой + правила.

### Примитивы
| Компонент | Назначение | Состояния (§11) |
|---|---|---|
| Button | основное действие | Default/Hover/Pressed/Focus/Disabled/Loading; press-scale .97 |
| IconButton | иконка-кнопка | то же + accessible name обязателен (§15) |
| Input | текстовое поле | Default/Focus/Error/Disabled |
| Textarea | многострочный ввод | то же |
| Checkbox | булев выбор | Default/Checked/Disabled |
| Radio | выбор одного | Default/Selected/Disabled |
| Switch | тумблер (аналитика/уведомления) | On/Off/Disabled |
| Chip | date/priority/label и т.п. теги | Default/Selected/Removable |
| Divider | разделитель | — |
| Tooltip | подсказка | — |
| Spinner | индикатор загрузки | — |

Из DS-бандла (СИМПАС), которые прототип реально использует и на которые нужно ориентироваться по паттерну (не 1:1 API): `Badge` (варианты confirmed/pending/secondary/new/…), `Card`/`CardHeader`/`CardBody`, `SegmentedControl`, `Icon` (24 viewBox, stroke 1.75, currentColor), `ServiceMark`.

### Навигация
BottomNav, Sidebar, TopBar, SegmentedControl, Tabs, Breadcrumb, CommandPalette.
- BottomNav состояния: активный пункт (forest), обычный (muted), центральная кнопка `+` (форест-круг, приподнята `margin-top:-16px`).
- CommandPalette: Cmd/Ctrl+K, единая командная модель (D15), фильтрация по вводу + Enter на первом совпадении.

### Task
TaskCheckbox, TaskRow, TaskMetadata, FocusMarker, TaskDetail, SubtaskRow, ChecklistRow, TaskMenu.
- Task-специфичные состояния (§11): Normal / Focus / MissedPlan / DeadlineSoon / DeadlineMissed / Recurring / Completed / Selected / Dragging. **Никогда не только цветом** — есть текст/иконка/структура (overdue: `!`-бейдж + подпись «до 27 авг»; focus: золотой контур + точка-маркер; selected: заливка checkbox + фон строки `sage-100`).

### Planning
DateChip, TimeChip, DurationChip, DeadlineChip, ReminderChip, RecurrenceChip, DatePicker, TimePicker, TemporalConflict, future CalendarTask/Event.

### Organization
ProjectRow, ProjectHeader, Section, BoardColumn/Card, Label, Priority, Filter.

### Capture
QuickAdd, Composer, NLPToken (редактируемый/удаляемый chip, `×`), InheritedContextChip, ParsingPreview, DraftIndicator.

### Overlay
BottomSheet, Modal, SideInspector, Menu, Popover.
- Desktop Context Menu — паттерн из прототипа: частые действия сверху («Выполнить», «В Главное сегодня», «Перепланировать», «Когда будет время»), разделитель, затем реже используемые («Изменить проект», «Приоритет», «Метки»), второй разделитель, затем единственный destructive пункт снизу («Удалить», красный/жирный).

### Feedback
Toast, UndoToast, EmptyState, Loading, Error, Offline, SyncState.
- UndoToast — тёмный форест-фон (`--forest-900`), белый текст, золотая (`--gold-400`) ссылка «Отменить», плавает над контентом (`--shadow-floating`).

### Account/Data
SignIn, OtpInput, SyncStatus, DataPrivacyRow, Entitlement/Paywall.

### 2.1 Дополнительные компоненты, не показанные в прототипе, но обязательные (`04_UI_DESIGN_SYSTEM.md` §11.1)

ProjectCreateEditSheet, SectionCreateRename, ProjectArchive/Delete, RestoreContextSheet, RecurringSubtaskScopeSheet, WebReminderCapabilityNotice, AndroidExactAlarmCapabilityNotice, LocalWorkspaceStash, BackupRestoreModeSheet — «required states of approved behavior, not a new visual direction», т.е. собираются из тех же примитивов/паттернов, отдельного визуального языка для них проектировать не нужно, но экраны нужно **сделать с нуля** (в прототипе их нет).

### 2.2 Иконки (§12)

Одна line-family, generic-иконки в стиле Lucide-эквивалента: 24 viewBox, 1.75 stroke, `currentColor`, round caps/joins. Кастомные SIMPAS/сервис-иконки — где применимо. **Никакого emoji-icon-system.** Именованный набор в DS-бандле (`components/icons/Icon.jsx`, см. `_ds_manifest.json`) — заимствованный из СИМПАС набор для заметок/действий психолога (`request, anamnesis, observation, intervention, resources, dynamics, homework, next_step, private, for_client, quote, hypothesis, search, add, filter, import, export, share, archive, delete, save, close, back, mic, attach, tags, more, sync, meeting, payment, format, list`) — ШАГИ использует только подмножество, реально задействованное в прототипе (add, archive, back, close, delete, format, list, meeting, more, search, mic, attach — видно по `x-import` вызовам), и потребуется **добросить недостающие task-manager-специфичные иконки** (чекбокс/повтор/приоритет/метка/фильтр как отдельная иконка от «filter» СИМПАС, drag-handle, calendar/date-picker, notification-bell) — их в бандле нет.

## 5. Доступность

Блокирующие релиз требования (`04_UI_DESIGN_SYSTEM.md` §15):
- **WCAG 2.2 AA** для Web; AA-контраст текста.
- Полная клавиатурная доступность desktop/web.
- Логичный focus order.
- Модальный focus trap + возврат фокуса после закрытия.
- Accessible names у icon-only кнопок.
- Семантические heading/landmarks.
- `aria-live="polite"` для завершения/синка, **не шумные** объявления при reorder.
- **Альтернатива drag** для любой drag-операции (подтверждено также `01_PRODUCT_BEHAVIOR_R1.md` §13: «Every drag operation has accessible context-menu/keyboard alternative»; Board виртуализируется >200 карточек).
- Reduced Motion (см. §7 Motion: убирает translate/scale, оставляет fade ≤100ms).
- 200% zoom без потери функциональности/контента.
- Ошибки полей связаны программно (aria-describedby/aria-invalid и т.п.).
- **Никакого swipe-only критичного действия** — критично для Inbox Process (M13): в прототипе жест «← смахните, чтобы пропустить» сопровождается видимыми кнопками-альтернативами («Сегодня/Дата/Проект», «Пропустить →», «Удалить»), т.е. swipe — ускоритель, не единственный путь.

Автоматизированное тестирование a11y (`06_TESTING_ACCEPTANCE.md` §7): axe (автоматика) + ручная проверка клавиатурой + TalkBack + NVDA (future VoiceOver); 200% zoom, reduced motion, dark/light контраст, альтернатива drag — всё входит в приёмку.

Target-size: touch target ≥44×44 логических px (§6, общий для всех интерактивных элементов, не только кнопок).

Board (drag-n-drop) — клавиатурная альтернатива обязательна per задача/карточку (context menu «Переместить в раздел…» и/или Cut/Paste-паттерн — конкретный механизм не специфицирован, решение за реализацией).

## 6. Гейты адгезии (`_adherence.oxlintrc.json`)

Файл — шаблон линт-конфига из бандла СИМПАС (`x-omelette` namespace), НЕ готовый конфиг ШАГИ, но задаёт паттерн, который `packages/ui`/`packages/app` обязаны воспроизвести под свои токены/компоненты (согласуется с `04_UI_DESIGN_SYSTEM.md` §16 «Token/string enforcement» — CI сканирует код).

Что запрещено (`no-restricted-syntax`, `oxlint`/ESLint-совместимые селекторы):
1. **Сырой hex-цвет** в литерале (`/#[0-9a-fA-F]{3,8}\b/`) — обязан идти через `var(--token)`.
2. **Сырое px-значение** в литерале (`/\b\d+px\b/`) — обязан идти через spacing/radius токен.
3. **`font-family`, отличный от Geist/Geist Mono** — единственные разрешённые семейства.
4. Импорт внутренностей компонентов дизайн-системы напрямую (`components/brand/**`, `components/core/**`, `components/icons/**`, `components/navigation/**`, `ui_kits/**`) — обязан быть через публичный `index.js` (единая точка экспорта). Исключение — сами файлы `**/index.js` (override отключает правило).
5. **Закрытый список пропсов** на конкретные компоненты (JSX-селекторы бьют по имени элемента): `Badge` (только `variant, dot`), `Button` (`variant, size, block, leadingIcon, trailingIcon`), `Card` (`interactive, padding`), `Icon` (`name, size, strokeWidth`), `Input` (`leading, trailing, wrapperStyle`), `SegmentOption` (`value, label, icon`), `Separator` (`orientation`), `ServiceMark` (`service, size, shape, bare`) — плюс общие React-пропсы (`key, ref, className, style, children`).
6. **Закрытый список значений enum-пропсов**: `Badge.variant` ∈ {default, secondary, outline, confirmed, pending, completed, cancelled, paid, processing, new}; `Button.variant` ∈ {primary, accent, secondary, ghost, destructive}; `Button.size` ∈ {sm, md, lg}; `Separator.orientation` ∈ {horizontal, vertical}; `ServiceMark.shape` ∈ {squircle, rounded, circle}.

Как это ложится на CI: правила все выставлены на `"warn"` в исходном файле — для продукта ШАГИ это нужно решить осознанно (warn допускает merge с нарушениями, error — блокирует CI; учитывая формулировку §16 «CI scans code… forbidden», разумно поднять минимум hex/px/font-family правила до error). `no-restricted-imports` — тот же принцип «single entry point» для `packages/ui`. **Граница token-layer**: всё, что не в `tokens/*.css` (или их ШАГИ-аналоге), не имеет права появляться как литерал в компонентах/экранах — только `var(--...)`. Список токенов и их `tokenKinds` (color/font/spacing/radius/shadow/other) в `x-omelette.tokens`/`tokenKinds` — это машиночитаемый реестр, который стоит воспроизвести для токенов ШАГИ, чтобы линтер знал полный allowlist.

Отдельно — §16.1 Localization acceptance (`04_UI_DESIGN_SYSTEM.md`): **user-facing литеральные строки в reusable component implementation тоже запрещены** — это НЕ покрыто данным `.oxlintrc.json` (там нет правила против строковых JSX children), значит для ШАГИ нужно **добавить своё правило** (i18n-строки только через каталог/слоты, ничего в `packages/ui`).

## 7. i18n

(`00_MASTER_IMPLEMENTATION_TZ.md` §13.1, `04_UI_DESIGN_SYSTEM.md` §16.1, §5 default locale в §5 «Default locale: `ru-RU`; Monday-first; 24-hour time»)

- Дефолтная и единственная в R1 локаль — **`ru-RU`**, обязана быть полной. Отсутствующий ключ / fallback-to-key в production-сборке — **CI failure**.
- Каждая user-facing строка живёт в i18n-каталоге; **компоненты `packages/ui` не содержат литеральной продуктовой копии** — принимают текст через props/slots/ключи.
- Дата/время форматируются через locale-слой, никогда не через хардкод названий месяцев в domain-логике (недели — Monday-first, время — 24-часовое).
- Архитектура должна допускать будущие локали без форка компонентов/domain-поведения.
- Верстка обязана проходить проверку на **длинные русские строки** и **200% zoom** (§16.1 «Layout validation includes long Russian strings and 200% zoom») — т.е. в тест-сьют закладывается стресс-тест на переполнение текстом (кнопки/чипы/заголовки на русском обычно длиннее английских аналогов).
- Копирайтинг-тон (§18): взрослый, лаконичный, спокойный, человечный; без инфантилизации/hype/корпоративного жаргона/геймификации. Примеры эталонных фраз: «На сегодня всё.», «Входящие разобраны.», «Здесь пока нет задач.», «Нет соединения. Изменения сохранятся на устройстве.», «Перенести на завтра?». Избегать технического текста ошибок и англоязычной implementation-терминологии в русском UI.
- Иллюстративные даты/примеры из VECTOR CJM **не являются доменной истиной** — прод всегда рендерит parser-resolved точную локальную дату (§18.1 «Important production corrections», п.2 — CJM-пример «до пятницы, 5 сент» датирован неверно для 29.08.2026, реальная следующая пятница — 04.09.2026).

Где именно лежит каталог строк (файл/формат/пакет) — **в изученных файлах не специфицировано** (см. раздел 10, открытый вопрос).

## 9. Визуальная регрессия

(`04_UI_DESIGN_SYSTEM.md` §17, `06_TESTING_ACCEPTANCE.md` §1 «Visual: production screenshots against approved handoff semantics»)

- Продакшн-компоненты генерируют канонические скриншоты («canonical screenshots»); стек — Web Playwright (§1 test pyramid), для Android — Maestro/Appium-equivalent, Windows — Tauri/WebDriver, iOS/macOS — future smoke.
- Порог провала: **>2px** непредвиденного расхождения ключевой геометрии, или несовпадение токена/цвета — фейлит ревью. Рендеринг шрифта допускает платформенную толерантность, но метрики/layout обязаны совпадать.
- **Golden states** обязаны включать: все состояния из handoff (см. таблицу §3 выше, столбец «В прототипе: да») **плюс** продакшн-only edge-состояния — temporal conflict, attachment pending, account merge, offline (эти explicitly названы в §17 как обязательные к baseline, хотя не показаны в HTML).
- Т.к. `ru-RU` и 200% zoom — обязательная валидация верстки (§16.1), в baseline логично закладывать снапшоты с длинными русскими строками и с 200%-зумом как отдельными вариантами каждого ключевого экрана (это явно не сформулировано как «visual regression» пункт напрямую, но вытекает из пересечения §16.1 и §17 — см. открытые вопросы).
- Baseline обязателен для 3 продуктовых тем: System/Light/Dark (paper/graphite/ink исключены явно).

## 10. Открытые вопросы

1. **Где физически хранится i18n-каталог и в каком формате** (JSON/ICU MessageFormat/gettext/что-то ещё), кто владеет ключами (packages/app? отдельный packages/i18n?) — ни в `04_UI_DESIGN_SYSTEM.md`, ни в `00_MASTER_IMPLEMENTATION_TZ.md` формат не специфицирован, только принцип «catalog/keys». Решение владельца нужно перед тем, как проектировать API компонентов, принимающих текст.
2. **Расхождение desktop sidebar-состава**: `04_UI_DESIGN_SYSTEM.md` §9 перечисляет «Сегодня, План, Входящие, Проекты, Фильтры, Метки, Завершённые» как раздельные пункты; в HTML-прототипе (`sec-desktop`, D01) реально нарисовано «Сегодня, План, Входящие, [Проекты-секция], Избранное / Фильтры (одна строка), Метки, Завершённые» — т.е. «Избранное» и «Фильтры» слиты в один пункт визуально, при этом текст спека их не упоминает как единый пункт вовсе. Нужно решение: три отдельных пункта или «Избранное/Фильтры» — комбинированный.
3. **PWA manifest / desktop icon exact spec** — не зафиксирован в normативных файлах список требуемых размеров/purpose для `manifest.json`, `.ico`, `.icns` — придётся зафиксировать самостоятельно (стандартный набор) без явной опоры на спек.
4. **Android adaptive icon safe-zone факт vs заявление**: readme.md бандла СИМПАС утверждает «дерево в 62dp безопасной зоны» как общее правило набора, но фактический масштаб-фактор в `ic_launcher_foreground.svg`/`ic_launcher_monochrome.svg` (0.20013 от исходных 500px-координат на 108dp канве) визуально даёт заметно больше — стоит визуально сверить на реальных OEM-масках (круг/squircle/квадрат/капля) перед тем, как считать эти 3 SVG production-ready «as is».
5. **`_adherence.oxlintrc.json` — все правила `"warn"`, не `"error"`** — спецификация (§16 «CI scans code… forbidden») подразумевает жёсткий гейт, но поставленный шаблон линтера мягкий. Владельцу нужно решить severity для ШАГИ-версии конфига, и явно нет правила против литеральных user-facing строк в JSX children (только hex/px/font-family/props/imports) — придётся дописывать самим под §16.1.
6. **Компонентный API DS-бандла (СИМПАС) не является API `packages/ui` ШАГИ** — `_ds_manifest.json`/`_adherence.oxlintrc.json` целиком описывают чужой продукт (Badge/Card/SegmentedControl/ServiceMark и их пропсы — из мира психологов/клиентской записи). Нужно явное решение: сколько из этого API копируется буквально (Button/Badge/Card/Input/Separator/SegmentedControl выглядят достаточно generic, чтобы взять как есть) против переосмысления под задачник (TaskRow/TaskCheckbox/BottomNav/BoardColumn и т.п. — их вообще нет в бандле, только в текстовом §10 задании).
7. **Иконки-глифы для задачника отсутствуют в поставленном Icon-наборе** (нет repeat/recurrence, priority, label/tag, notification-bell, drag-handle, checklist-item, calendar/date-picker глифов среди `ICON_NAMES` СИМПАС) — либо расширять кастомный набор, либо подключать Lucide-эквивалент по строгому визуальному языку 24/1.75/currentColor/round.
8. **Прототип покрывает меньше половины экранов из матрицы буквально** (см. столбец «В прототипе» в разделе 3: из 52 mobile ID нарисовано 16 напрямую + 3 частично; из 20 desktop — 6). Остальные ~30 mobile / 14 desktop / 6 tablet / 21 system-state / 8 из 14 Vector-состояний нужно спроектировать «по духу DS», без опорного визуального образца — это крупнейший источник неопределённости объёма и субъективности решений при декомпозиции задач.
9. **Fonts self-host**: сами `.woff2`-файлы Geist/Geist Mono физически не поставлены нигде в репозитории (`docs/spec/DESIGN/design-system/tokens/fonts.css` только `@import` из Google Fonts, что сам спек запрещает в runtime) — нужно раздобыть официальные файлы (Vercel Geist — открытая лицензия) и упаковать в `packages/ui`, это отдельная невидимая с первого взгляда задача.
10. **`ШАГИ-handoff_design_v2.zip`** (архив) лежит нераспакованным в `docs/spec/DESIGN/` рядом с уже распакованным `source_unpacked/` — не открывался (задание не просило), возможно избыточен/дублирует `source_unpacked/`, либо содержит доп. ассеты (шрифты? иконки?) не увиденные в этом исследовании — стоит проверить отдельно, если понадобятся файлы шрифтов из п.9.

## Сводка влияния на объём работ

Наибольшее влияние на объём UI-работы, по убыванию:

1. **Прототип покрывает буквально ~30% экранов матрицы** (16/52 mobile, 6/20 desktop нарисованы) — большинство состояний (empty/dense/error/offline/paywall/import/settings-root/date-pickers/recurrence-editors и т.д.) нужно спроектировать с нуля по токенам/паттернам, а не «перенести» готовую картинку.
2. **DS-бандл — чужой продукт (СИМПАС/ПРАКТИКА), не ШАГИ** — токены переиспользуются 1:1, но компонентный API/иконки/названия нужно пересобрать под задачник; нужно явное решение, что копируется буквально, а что переосмысляется.
3. **Self-host шрифтов физически отсутствует** — Google Fonts `@import` в поставленном бандле прямо запрещён спеком; нужно добыть/упаковать `.woff2`.
4. **21 системное состояние (ST01–ST21) + 11 доп. edge-состояний без визуального образца** — требуют отдельного проектирования Loading/Error/Offline/Conflict/EmptyState компонентов и их применения в каждом экране.
5. **Жёсткий accessibility-гейт как release blocker** (WCAG 2.2 AA, keyboard-alternative для каждого drag/swipe, focus trap, 200% zoom, aria-live) плюс обязательная visual regression baseline с допуском >2px — увеличивает объём тестовой/QA-инфраструктуры пропорционально числу экранов, а не линейно с «просто нарисовать».
