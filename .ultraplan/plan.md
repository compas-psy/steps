## Раскладка монорепозитория
Строго по `SPEC/00_MASTER_IMPLEMENTATION_TZ.md §3`, с одним добавлением
(`packages/i18n`, оформляется ADR-0004):

```
apps/{web,desktop,mobile}          — только оболочки, ни одного экрана
packages/contracts                 — DTO / Zod / типы под OpenAPI
packages/core                      — домен: сущности, команды, инварианты, время, повторы, rank
packages/storage                   — репозитории + адаптеры SQLite / IndexedDB
packages/sync                      — outbox, HLC, merge (в волне 1 — только форма данных)
packages/nlp                       — детерминированный русский парсер
packages/importer                  — Todoist / CSV / backup
packages/ui                        — токены и компоненты, без продуктовых строк
packages/app                       — ВСЕ экраны, маршруты, поведение
packages/i18n                      — каталоги строк, ICU, проверка полноты
packages/telemetry                 — только санированные контракты событий
packages/platform                  — интерфейсы возможностей платформы
server/, deploy/                   — каркас под волну 2
```

**Инвариант:** ни одного экрана, бизнес-правила, правила NLP/sync и ни одной
пользовательской строки в `apps/*`.

## Что закладывается с первого коммита, иначе переписывать
Из отчётов разведки — семь швов, которые поздняя вставка сломает:

1. **Единая точка входа `CreateTaskCommand`** — через неё идут Quick Add,
   импорт и все будущие адаптеры. Прямая запись в БД запрещена.
2. **Один domain-валидатор на 38 правил** — общий для локальных команд,
   входящих sync-патчей, натива и веба.
3. **Детерминированный UUIDv5** для occurrence / subtask / checklist повторов
   плюс remove-wins граница `stop_after_occurrence_seq`.
4. **Outbox пишется в той же локальной транзакции**, что и сущность.
5. **Per-field HLC и `revision`** на изменяемых сущностях.
6. **Tombstone вместо жёсткого удаления**, retention 90 дней.
7. **`capture_state`, `source`/provenance, snapshot имени проекта** на Task.

## Эпики и распределение по моделям

перепланирует. `sonnet` — всё, где есть логика или вкус; `haiku` — механическая
работа с однозначной спецификацией.

## Метод
Разработка по `superpowers`: TDD RED-GREEN-REFACTOR, самодостаточные задачи
субагентам, проверка перед объявлением готовности. Всё, что касается
интерфейса, — через `impeccable`. После каждого эпика: моя валидация, коммит,
пуш, короткий отчёт владельцу.

## Риски
- **~70% экранов матрицы не нарисованы** (16 из 52 мобильных, 6 из 20
  десктопных, ST01–ST21 — ни одного). Проектируются по токенам; нормативна
  матрица `12_SCREEN_STATE_MATRIX.md`, а не картинка.
- **DS-бандл — слепок чужого продукта** (ПРАКТИКА). Токены совпадают 1:1,
  компонентный API нет. Задачные компоненты пишутся с нуля.
- **Шрифтов Geist нет в поставке**, а поставленный `fonts.css` тянет Google
  Fonts, что ТЗ прямо запрещает. Вендорим `.woff2` из пакета Vercel (SIL OFL).
- **Перф-бюджеты — релизные гейты без определённого стенда.** Android
  «mid-range» замораживается конкретной моделью в ADR-0003.
- **Подпись Android — точка невозврата.** Схема заимствуется у Записок
  целиком, fail-closed (`.ultraplan/research/04-android-release.md`).
- **Веб обязан повторить семантику ранжирования FTS5** один-в-один. Пишется
  дважды, проверяется общими golden-тестами.
