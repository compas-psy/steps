## Раскладка монорепозитория
Строго по `SPEC/00_MASTER_IMPLEMENTATION_TZ.md §3`, с одним добавлением
(`packages/i18n`, оформляется ADR-0004):

```
apps/{web,desktop,mobile}          — только оболочки, ни одного экрана
packages/contracts                 — DTO / Zod / типы под OpenAPI
packages/core                      — домен: сущности, команды, инварианты, время, повторы, rank
packages/storage                   — репозитории + адаптеры SQLite / IndexedDB
packages/sync                      — outbox, HLC, merge (в волне 1 — только форма данных)
packages/nlp                       — детерминированный русский парсер
packages/importer                  — Todoist / CSV / backup
packages/ui                        — токены и компоненты, без продуктовых строк
packages/app                       — ВСЕ экраны, маршруты, поведение
packages/i18n                      — каталоги строк, ICU, проверка полноты
packages/telemetry                 — только санированные контракты событий
packages/platform                  — интерфейсы возможностей платформы
server/, deploy/                   — каркас под волну 2
```

**Инвариант:** ни одного экрана, бизнес-правила, правила NLP/sync и ни одной
пользовательской строки в `apps/*`.

## Что закладывается с первого коммита, иначе переписывать
Из отчётов разведки — семь швов, которые поздняя вставка сломает:

1. **Единая точка входа `CreateTaskCommand`** — через неё идут Quick Add,
   импорт и все будущие адаптеры. Прямая запись в БД запрещена.
2. **Один domain-валидатор на 38 правил** — общий для локальных команд,
   входящих sync-патчей, натива и веба.
3. **Детерминированный UUIDv5** для occurrence / subtask / checklist повторов
   плюс remove-wins граница `stop_after_occurrence_seq`.
4. **Outbox пишется в той же локальной транзакции**, что и сущность.
5. **Per-field HLC и `revision`** на изменяемых сущностях.
6. **Tombstone вместо жёсткого удаления**, retention 90 дней.
7. **`capture_state`, `source`/provenance, snapshot имени проекта** на Task.

## Метод
Разработка по `superpowers`: TDD RED-GREEN-REFACTOR, самодостаточные задачи
субагентам, проверка перед объявлением готовности. Всё, что касается
интерфейса, — через `impeccable`. После каждого эпика: моя валидация, коммит,
пуш, короткий отчёт владельцу.

## Риски
- **~70% экранов матрицы не нарисованы** (16 из 52 мобильных, 6 из 20
  десктопных, ST01–ST21 — ни одного). Проектируются по токенам; нормативна
  матрица `12_SCREEN_STATE_MATRIX.md`, а не картинка.
- **DS-бандл — слепок чужого продукта** (ПРАКТИКА). Токены совпадают 1:1,
  компонентный API нет. Задачные компоненты пишутся с нуля.
- **Шрифтов Geist нет в поставке**, а поставленный `fonts.css` тянет Google
  Fonts, что ТЗ прямо запрещает. Вендорим `.woff2` из пакета Vercel (SIL OFL).
- **Перф-бюджеты — релизные гейты без определённого стенда.** Android
  «mid-range» замораживается конкретной моделью в ADR-0003.
- **Подпись Android — точка невозврата.** Схема заимствуется у Записок
  целиком, fail-closed (`.ultraplan/research/04-android-release.md`).
- **Веб обязан повторить семантику ранжирования FTS5** один-в-один. Пишется
  дважды, проверяется общими golden-тестами.

### E01 — закрыт (домен, время, Task, инварианты, rank)
Доменные типы и модель времени на `@js-temporal/polyfill`, детерминированные
идентификаторы (UUIDv7 для сущностей, UUIDv5 для occurrence-повторов),
дробные ранги (base62, LexoRank-подобные), единый валидатор на 38 правил,
командный слой `CreateTaskCommand`/`UpdateTaskCommand`/`CompleteTaskCommand`/
`DeleteTaskCommand` с инверсией порта хранилища (ADR-0003 — избегает
циклической зависимости `storage → core → storage`). `packages/core`: 41
файл теста, 317 тестов.

### E02 — закрыт (локальное хранилище: SQLite/IndexedDB, миграции, FTS)
Контракт хранения (`StoragePort`/`DomainMutation`/`EntityWrite` — outbox
физически нельзя не записать вместе с сущностью), эталонная in-memory
реализация, SQLite-адаптер (`node:sqlite`, ADR-0005) и IndexedDB-адаптер (13
object store), общее платформонезависимое ранжирование поиска с
golden-датасетом, прогоняемым против обоих движков (FTS5 и inverted index)
для гарантии идентичного результата. `packages/storage`: 23 файла теста,
164 теста.

### E03 — закрыт (продакшн дизайн-система, харнесс a11y и визрегрессии)
Девять категорий компонентов `@shagi/ui` (примитивы, навигация, оверлеи,
feedback, задачи, планирование, организация, захват, аккаунт/данные) — 65
компонентов, presentational-архитектура проверяется в каждом пакете работ
собственным AST-сканером запрещённых импортов домена/i18n/nlp/Temporal.
Харнесс a11y и визрегрессии (`packages/ui/dev/` — dev-only витрина, не
продуктовый экран, поэтому не в `apps/*`; `packages/ui/e2e/{a11y,visual}
.spec.ts` — axe WCAG 2.2 AA + 16 скриншот-baseline обеих тем), job
`nightly.yml/visual-regression` подключён (ждёт, пока владелец заведёт
переменную репозитория `ENABLE_VISUAL_REGRESSION=true`).

Найдено и исправлено харнессом при первом же прогоне, не на слово из
отчёта: `aria-selected` на `<div>` без роли (TaskRow — роль теперь явный
опциональный проп, компонент не может знать структуру родительского
списка); `CommandPalette` без доступного имени поля ввода и с зависшим
`aria-controls` при пустом списке (попытка чинить в одну сторону сама
сломала `aria-required-attr` — поймано повторным прогоном харнесса, не
только typecheck); `Button` в состоянии loading реально убирала текст
кнопки из accessibility tree через `visibility:hidden`, хотя комментарий
рядом утверждал обратное; широкий контрастный разрыв на уровне токенов
(500-тона использовались как текст на нейтральной поверхности вместо
фона, для которого посчитаны — 2.2–4.2:1 вместо порога 4.5) в
Badge/Chip/SegmentedControl/Input/Textarea/Menu/TemporalConflict/Sidebar/
BottomNav/Tabs/BoardCard/ProjectRow, исправлено на уровне токенов
(`--amber-500`/`--red-500`-соседи плюс новый `--primary-on-surface`), не
точечными переопределениями. `packages/ui`: 83 файла теста, 1105 тестов
vitest + 18 тестов Playwright (2 a11y + 16 визрег).

`ScreenId`), не URL-роутер — референс `compas-psy/zapiski`, тот же приём.
`AppHost.storageBackend` — плоское описание адаптера ('indexeddb'|
'memory'), не готовый `StoragePort`: первая версия строила
`IndexedDbStorage` прямо в `apps/web/src/main.tsx`, гейт границы `apps/*`
поймал это как обход (`@shagi/storage` напрямую, минуя `@shagi/app`) —
`@shagi/app` резолвит описание сама, оболочка передаёт только данные.
Заодно нашли и починили: `apps/web/src/platform.ts` держал `localDb:
Unavailable` с комментарием «ещё не поставлен» — устарело, `@shagi/storage`
готов с E02; реальное хранилище на вебе теперь IndexedDB. `apps/desktop`/
`apps/mobile` — `{kind: 'memory'}` как честный временный вариант (нет
Rust-тулчейна для Tauri SQL-плагина в этой среде).

Экраны M01–M05 (`12_SCREEN_STATE_MATRIX.md`): Launch (мгновенный переход,
без фейкового лоадера), Welcome («Начать» локально / «Войти»), Sign in
(эпик E04/E15 — реального бэкенда в R1a нет, попытки входа честно

использование стека — `createTaskCommand` через реальный `useStorage()`,

честная формулировка без AI-маркетинга). M06 Today Empty сознательно не

прямой импорт `@shagi/storage` (выше); `packages/core/src/index.ts` не

### E05 — частично (golden-корпус ≥800 закрыт; Quick Add UI — не начато)
`packages/nlp/src/corpus/golden-corpus.ts`: 299 → 807 кейсов (`01§4`
требует ≥800), все `expected*` взяты из реальных прогонов `parseQuickAdd`,
не угаданы — покрыты все шесть обязательных граней (false positives,
quoted spans, границы месяца/года, високосные годы, комбинированные
выражения, кириллическая пунктуация). Лично воспроизведена адверсариальная
проверка (испорчено ожидание, тест упал именно на испорченном кейсе,
восстановлено — снова зелено).

**Не начато осознанно**: экраны M20–M23 (Quick Add Empty/NLP Parsed/NLP
Ambiguous/Quick Add Expanded, `12_SCREEN_STATE_MATRIX.md`) и «Contextual
Quick Add» (`01§3` — inherited chips от Today/Plan/Project, draft
autosave, `Ctrl/Cmd+N`). Причина отсрочки: контекстное наследование
завязано на реальные origin-экраны (Today/Plan/Project), которых на
момент этого решения не было ни одного (E06 только начинался) — строить
полноценный Quick Add без единого реального места вызова означало бы
проектировать под гипотетическое использование раньше времени. Возврат к
этому — естественно вместе с E06/E09/E12, когда появится хотя бы один
реальный origin-экран.

### E06 — частично (M06/M07 закрыты; M08 и интерактивные действия — не начаты)

**Не начато осознанно**: M08 (виртуализация плотного списка, 20+/50

рабочими. Оба — естественные следующие пакеты работ внутри того же
эпика E06.
